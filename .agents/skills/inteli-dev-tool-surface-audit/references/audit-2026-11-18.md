# Аудит поверхности инструментов — 2026-11-18

Повод: в CRM появились три новые доменные возможности — **баланс пользователя**,
**self-проекты** и **объединение ролей** (клиент/исполнитель → пользователь).
Проверялось, что каждая получила владельца в MCP и у Кики, а старые поверхности
не разъехались после переименования ролей.

## Что изменилось в домене

| Возможность | Где живёт | MCP | Кики |
|---|---|---|---|
| Баланс пользователя и история операций | `users.balance`, `balance_transactions`, карточка пользователя | `get_balance` (новый) | `get_balance` (новый) |
| Ручная корректировка баланса (+/−, минус допустим) | `POST /admin/clients/{id}/balance` | `adjust_balance` (confirm, новый) | `adjust_balance` (confirm, новый) |
| Self-проект: заказчик — администратор | `projects.type`, форма проекта | `create_project` с `type: self` | `create_project` с `type: self` |
| Автосчёт при завершении задачи | `BalanceService::settleCompletedTask` | — (доменное следствие) | — (доменное следствие) |
| Роль «пользователь» вместо клиента/исполнителя | `users.role`, `User::roleNames()` | `list_users` фильтр `admin/user` + `balance` | роли в каталоге через `roleNames()` |
| Отчёты/брифы пользователей | `/reports`, `/briefs` | уже были | уже были |

Решения:

- **Баланс — read в обе поверхности, запись в обе с `confirm`.** Это денежное
  действие, поэтому MCP требует `confirm=true`, а Кики показывает подтверждение
  в чате (`confirm: true` в каталоге).
- **Клиент видит только свой баланс.** `get_balance` без `user_id` возвращает
  баланс текущего пользователя; чужой — только администратор.
- **Self-проект — параметр `type`, а не отдельный tool.** `client_id` для него
  игнорируется, заказчиком становится создатель-админ (логика в `ProjectService`).
- **Автосчёт и списание при завершении задачи не выставляются в MCP/Кики.**
  Это следствие доменного перехода статуса, а не отдельная операция; агент
  завершает задачу через `update_task_status`, счёт создаётся сам.
- **Старые значения роли принимаются на входе.** `list_users(role: client|executor)`
  маппится на `user`, чтобы внешние клиенты не сломались после миграции.

## Остаточные gaps

- В MCP `create_task` нет structured-шаблона (`form_template_id`/`form_data`):
  создание из формы остаётся UI-сценарием и `create_task_from_form` у Кики.
  Причина: шаблонные поля валидируются схемой, а MCP-клиенту проще передать
  готовое описание; решение можно пересмотреть при внешнем потребителе.
- Экспорт баланса/операций в файл отсутствует — при необходимости это `get_balance`
  с форматом, а не файловый стрим.
- Сайт и ядро не затрагивались: баланс и проекты принадлежат CRM.
