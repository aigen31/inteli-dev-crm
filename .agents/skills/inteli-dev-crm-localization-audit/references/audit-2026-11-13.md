# Localization audit 2026-11-13

## Catalog

- **1,725 keys**; `en` and `zh` columns complete; no empty values or
  placeholder mismatches at the catalog level.
- Locale lists match: `en`, `ru`, `zh_CN` in JS, Inertia middleware and
  `LocaleController`.
- Values equal to the Russian key are allowlisted: `Windows XP`, `03 Steps`,
  and the technical regex `/[^a-zа-я0-9]+/u`.
- **94 case-insensitive duplicate keys with different translations** — review
  whether the pair is intentional (e.g. `Кики` name vs `кики` common word)
  before merging.

## UI surface

The Vue template scan finds **88 unique Russian strings** not present in
`messages.json`. Examples: `Ссылка для сброса пароля`, `Сброс пароля`,
`Предыдущий месяц`, `Задачи на день`, `Виджеты`, `Панель виджетов`,
`Поделиться`, `Передать клиенту`, `Загружаю…`.

Some are line fragments assembled at runtime (`Для`, `до`, `символов`,
`· для всех`) and need a composite key rather than a standalone one. Dynamic
values, AI prose, textareas and `data-i18n-skip` are excluded.

This is the main maintenance risk: the catalog can be structurally perfect
while a new Vue label stays Russian in EN/ZH. Re-run after every UI edit.

## Known gaps / decisions

- Some pages use composite strings assembled at runtime; those need manual
  smoke checks in EN/ZH.
- `translateDom` intentionally skips AI prose and `[data-i18n-skip]`.
- The catalog has no pluralization engine; count forms are translated as one
  string and must read naturally for all counts.
