# Тесты и проверка изменений

## Текущее состояние

Автотестов нет: каталог `tests/` отсутствует, хотя `phpunit.xml` ждёт `tests/bootstrap.php`, `tests/Unit` и `tests/Feature`. Production-образ собирается без dev-зависимостей, поэтому `php artisan test` там не определён.

Пока тестового набора нет, изменение считается проверенным после ручного сценария (ниже) и успешной сборки.

## Когда добавляете тесты

- Фреймворк — Pest 4 (`pestphp/pest`, `pest-plugin-laravel`) поверх PHPUnit 12.
- Создайте `tests/bootstrap.php`, `tests/Pest.php`, `tests/TestCase.php` вместе с первым тестом — без них `php artisan test` не стартует.
- Тестовая БД — sqlite `:memory:`, очереди/кэш/сессии — array/sync (см. `phpunit.xml`).
- Тесты запускайте в окружении с dev-зависимостями (`composer install`), не в production-образе.

## Линт

```bash
composer install          # dev-зависимости
./vendor/bin/pint --dirty
```

Стиль PHP: `declare(strict_types=1)`, нативные enum, типизированные свойства и возвращаемые значения.

## Ручная проверка по типу изменения

- **Backend/домен:** `php artisan migrate`, затем пройти сценарий в браузере или через curl; проверить статусы и уведомления.
- **Оплата:** создать счёт каждым способом (`yookassa`, `transfer`), проверить клиентскую страницу, ручное подтверждение и запрет онлайн-оплаты для перевода.
- **UI:** `npm run build`, открыть затронутые страницы на 1440px и 390px, проверить пустые состояния и мобильное меню.
- **Деплой:** после пересборки образа открыть `/up` и одну защищённую страницу.

CI-пайплайна в репозитории нет; проверки выполняются локально.
