# 0014. Полная поверхность CRM через MCP

## Контекст

MCP-сервер умел создавать отчёты и показывать несколько списков. Агентам нужен
весь рабочий контур CRM: клиенты, проекты и доступы, задачи, счета, отчёты,
шаблоны и пользовательские поля — с теми же правилами, что в UI.

## Решение

- MCP остаётся одним HTTP JSON-RPC endpoint с owner-level bearer-токеном.
- Доменные операции вынесены в `CrmMcpService`; контроллер отвечает только за
  JSON-RPC, auth и формат ошибок.
- Чтение — отдельные `list_*`/`get_*` tools; частые записи — именованные tools;
  остальные — `crm_operation` с явным enum операций.
- Отчёты используют шаблон **description + link**: MCP принимает
  `items[].description` и `items[].link`, а домен хранит `summary`/`test_url`.
- Денежные и разрушительные действия требуют `confirm: true`.
- Создание клиента требует `consent_confirmed: true` и пишет
  `consent_logs` (basis=contract, source=mcp).
- Секреты, API-токены и ключи платёжного шлюза намеренно не входят в MCP.

## Последствия

- Один `CrmMcpService` — точка расширения; новый домен добавляется tool-ом или
  операцией и тестом.
- Ошибки валидации возвращаются как `isError`, а не 500.
- MCP не обходит политики: действия идут через существующие actions/services.
- При росте поверхности `crm_operation` можно разложить на именованные tools без
  изменения домена.
