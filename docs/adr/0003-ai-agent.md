# ADR-0003: Tool-calling агент с подтверждением финансовых действий

## Статус

Accepted, 2026-10-31.

## Контекст

Кики должна помогать и владельцу, и клиентам: отвечать по своим данным, создавать задачи, применять шаблоны, менять поля, готовить счета. Прямой доступ LLM к ORM недопустим: prompt injection, утечка чужих данных, необратимые финансовые операции.

## Решение

- Провайдер — любой OpenAI-совместимый API; ключ шифруется в `settings`.
- `AgentService` ведёт цикл до 6 шагов: system prompt + контекст + история (40 сообщений) + tools.
- `CrmToolbox` — единственный реестр инструментов; видимость по роли, скоуп внутри обработчика по `user.id`.
- `create_invoice` и `mark_invoice_paid` помечены `confirm`: создаётся `ai_actions(status=proposed)`, UI показывает карточку, выполнение — только `POST /assistant/actions/{id}/confirm`.
- При confirm права и скоуп перепроверяются; TTL 30 минут; повторное выполнение невозможно.
- Все write-действия пишутся в `ai_actions`; сообщения и tool calls — в `ai_messages`.
- HTML из модели санитайзится перед сохранением; rate limit 30/мин; read-токен не может вызвать `/assistant/chat`.

## Альтернативы

- **LLM с SQL/ORM-доступом**: максимально гибко, но непредсказуемо и небезопасно.
- **Только чат без tools**: безопасно, но бесполезно для действий.
- **Автоматическое выполнение денег**: быстрее, но недопустимый риск.
- **Отдельный микросервис агента**: лишняя операционная сложность для одного Laravel-приложения.

## Последствия

- Агент предсказуем и аудируем; финансовые действия требуют человека.
- Список инструментов нужно поддерживать и тестировать (guardrail-тесты).
- Контекст и история ограничены, чтобы не раздувать токены.
- При смене провайдера достаточно изменить Base URL/модель.
