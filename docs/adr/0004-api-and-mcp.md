# ADR-0004: REST API v1 + MCP как прокси

## Статус

Accepted, 2026-10-31.

## Контекст

Нужно управлять CRM из ИИ-клиентов и получать данные программно. MCP-серверы популярных PMS/CRM либо дублируют бизнес-логику, либо проксируют публичный API. Дублирование логики в Node означало бы вторую модель прав и валидации.

## Решение

- REST API v1 в Laravel: `/api/v1`, bearer-токены (`api_tokens`, SHA-256), abilities `read|write`, expiry, роль наследуется от пользователя.
- Токены создаются только админом в UI и показываются один раз.
- API-контроллеры используют те же Action/Service и Resources; клиентские токены скоупятся по `client_id`.
- MCP-сервер — отдельный Node-процесс без зависимостей, вызывает REST API; tools/resources/prompts описаны в `mcp/src`.
- stdio — основной транспорт, HTTP — опционально для локальных клиентов.

## Альтернативы

- **MCP-сервер на PHP внутри Laravel**: меньше процессов, но сложнее транспорт и меньше совместимость с клиентами.
- **Прямой доступ MCP к БД**: быстрее, но дублирует права и валидацию.
- **Sanctum/Passport**: мощнее, но для single-tenant и одного вида токенов достаточно собственной таблицы; меньше зависимостей.
- **Только REST без MCP**: не решает сценарий «ИИ управляет CRM».

## Последствия

- Один контракт (REST) для людей, MCP и будущих интеграций.
- Нужно синхронно обновлять OpenAPI, MCP-схемы и тесты.
- Токен может утечь через логи/конфиги — хранится только хеш, plain показывается один раз.
- MCP не публикуется наружу; запускается рядом с CRM.
