# 0013. Кики знает интерфейс CRM: каталог помощи и инструмент `crm_help`

## Контекст

Кики умела работать с данными (задачи, клиенты, счета), но не знала карту интерфейса:
на вопрос «где пригласить участника» модель могла отвечать по догадке. Пользователю
нужны не общие советы, а точный раздел, ссылка и 1–3 шага.

## Решение

В CRM появился bounded context «Справочник интерфейса»:

- `CrmHelpService` — версионированный каталог разделов с ролями, путями, краткими
  описаниями, шагами и ключевыми словами. Источник истины — код CRM, отдельной БД нет.
- `crm_help` — read-only инструмент для kernel. Контракт: `query`, `page`, `limit`;
  ответ: `title`, `url`, `summary`, `steps`. Без подтверждения и без записи.
- В системный промпт всегда попадает компактная карта (роль + текущая страница), а
  модель обязана сначала вызывать `crm_help` для вопросов об интерфейсе.
- `/help` — пользовательский справочник по всем разделам с поиском и ссылками;
  Кики ссылается на него, если раздел не найден.
- Пустая страница чата предлагает help-вопросы; в ответах — markdown-ссылки.

## Границы и отказоустойчивость

- Каталог принадлежит CRM; kernel не хранит копию и не имеет доступа к БД CRM.
- Вызов синхронный и read-only. Если инструмент недоступен, в промпте остаётся карта —
  модель отвечает по ней; если раздела нет, говорит об этом и ведёт в `/help`.
- Никаких распределённых транзакций: помощь не меняет доменные данные.
- Существующий trace kernel показывает шаг `crm_help`; ошибки инструмента логируются
  в `AssistantToolController`, как и остальные tool-вызовы.

## Почему не отдельный микросервис

Каталог мал, меняется вместе с UI и не имеет собственного жизненного цикла. Выделение
в сервис сейчас дало бы сетевой вызов, вторую схему данных и риск рассинхронизации без
выгоды. Если появятся другие каналы и большой объём статей, retrieval можно вынести за
тем же контрактом `crm_help`, не меняя промпт и UI.

## Последствия

- Новый раздел CRM нужно добавить в каталог и тест покрытия; иначе Кики о нём не узнает.
- Ссылки в каталоге статические (списки/создание); конкретные сущности открываются
  через данные инструментов, а не выдуманные URL.
